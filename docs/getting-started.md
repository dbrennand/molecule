# Choose your path

Molecule tests Ansible roles, playbooks, and collections. Choose the path that matches the primary thing you are developing, not only the directories that happen to exist in the project.

## Start here

| If your primary goal is to... | Start with... | Typical starting shape |
| --- | --- | --- |
| Develop and verify one reusable role | [Test a role](getting-started-roles.md) | A role directory with `tasks/main.yml` and `molecule/default/` |
| Develop and verify one or more playbooks | [Test a playbook project](getting-started-playbooks.md) | An `ansible-creator` playbook project with root playbooks, inventory, and project configuration |
| Develop, package, publish, or test a collection | [Test a collection](getting-started-collections.md) | A collection with `galaxy.yml` and roles, plugins, modules, or other content |

### Test a role

Choose this path when the main question is whether a role produces the expected result. The role can be standalone or located inside another project. Start with the role-testing concepts when you are focused on the role's tasks, defaults, handlers, templates, variables, and resulting state.

A standalone role does not need to become a collection merely to be tested.

### Test a playbook project

Choose this path when the main question is whether a project’s playbooks work with its inventory and project configuration. The project generated by `ansible-creator init playbook` includes an adjacent collection with role(s). That collection is part of the playbook-project scaffold and does not automatically make this a collection-testing project.

Start with [Test a playbook project](getting-started-playbooks.md) when the scenario invokes root playbooks such as `site.yml` or `linux_playbook.yml`.

### Test a collection

Choose this path when the collection itself is the product under development. This includes collection metadata, packaging, publishing, collection dependencies, or testing several collection component types together.

Do not choose this path only because a playbook project contains an adjacent collection. Use [Test a playbook project](getting-started-playbooks.md) when the adjacent collection and its role are being exercised as part of the project’s root playbooks.

## The decision rule

Choose based on the primary development workflow:

```text
role behavior                         -> Test a role
root playbooks + inventory + config   -> Test a playbook project
collection package + components       -> Test a collection
```

A role inside an `ansible-creator` playbook project is therefore not a fourth journey. It is a component of the playbook-project journey unless the role or collection is being developed and tested independently of the project's root workflow.
